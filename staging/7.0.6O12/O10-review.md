15 October 2026. Unpublished; no GitHub commit or deployment. O9 is recorded as educationally approved in PROJECT-ROADMAP.md. An unchanged approved ZIP and checksum are preserved under Baseline-O9.

## Six-stage experience

1. **The investigation:** a short everyday connection, the concentration/mass question and a saved prediction.
2. **Equipment and method:** labelled apparatus, four method chunks with reasons, optional dilution example and slow device narration with complete visible text.
3. **Conduct the investigation:** weigh, immerse, blot/reweigh and record a batch. Wrong blotting receives an explanation beside the control. Six concentrations and three repeats each are recorded; after one batch the confident learner may run the rest with the same controlled method. No waiting animation.
4. **Analyse results:** O9 calculation steps, rate, per-repeat and mean tables, numeric point placement, optional plot support, a fitted trend and a justified approximate zero crossing. Raw readings are expandable to keep the main route short. Students save a conclusion.
5. **Evaluate:** three realistic repairs cover blotting, dimensions, precision/accuracy and repeatability; optional notes cover variables, resolution, bias, anomalies and follow-up concentrations.
6. **Apply independently:** two fresh forms of 12 structured items plus a written method/evaluation answer. Feedback follows the approved expandable O9 pattern, with submitted/correct answers and explanations. Writing has a model/checklist and no automatic score.

## Nine educational criteria

| Criterion | Evidence / reason to spend the time |
|---|---|
| Real life first | Limp vegetables lead directly to a measurable question. |
| Relatable and remembered | The same potato and blotting story is followed through data, graph and evaluation. |
| See/hear/understand/try/master | Apparatus and balance illustrations, optional slow method speech, reasons, guided data work, then unseen structured skills. |
| Progressive | O9 theory → controlled method → records → analysis → evaluation → fresh assessment. |
| Active participation | Prediction, method exploration, blotting decisions, recording, calculation, plotting and error repair. |
| Independent understanding | Models hidden until valid submission; assisted/repeated forms are practice. |
| Curriculum accuracy | Separate AQA-linked coverage review, explicit shared-tier and physical-practical limits. |
| Easy to understand | Visible reasons, short sections, large controls, nearby feedback, saved work and unlocked stages. |
| Engaging and efficient | One batch teaches the routine, remaining batches can be expedited; optional support and expandable raw data avoid repeated compulsory work. |

## Assessment, progress and preservation

RP02 uses the existing Biology board/course/tier record and sectionMastery architecture, adding rp02Lab rather than introducing a storage key or competing framework. Guided activity earns no mastery. Only valid, unseen, unassisted structured forms write the RP02 section score and section-scoped seen evidence; no whole-topic mastery is written. The dashboard calls this **Structured skills**, with writing still needing review. The percentage cannot establish physical laboratory competence.

A submitted answer is immutable through the answer handlers. Earlier forms, original writing and choices remain in history. Duplicate submissions do not add credit. Returning to learning, using help or leaving a pending check marks it assisted/practice; reload resumes without doing so. Repeated forms remain unscored. Invalid saved checks are kept for recovery and cannot restart a fresh evidence allowance. Reset cancellation and RP02-only reset preserve other lessons.

O1–O9 lesson files, question banks, media, original Osmosis video/subtitles, curriculum mappings, scoring helpers and existing navigation files are byte-identical to baseline. The new integration wraps RP02 routes; one old navigation test was updated because RP02 now opens an interactive lesson instead of the revision-only page. Preservation-manifest.json lists every comparison. Build identity and status metadata were updated, with the previous status note retained in Archive/Before-O10. The two end milestones were not developed.
